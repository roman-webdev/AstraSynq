# Live synthetic demo hosting research

Checked 2026-10-05. USD, before taxes. Official sources only. This is a planning snapshot, not a promise of account eligibility or uninterrupted free hosting. Account dashboards must be checked again before deployment; no accounts/resources were created. A missing published limit is marked unverified rather than assumed unlimited.

## Recommendation

Render Free web service (React static build + FastAPI at the same HTTPS origin), Neon Free PostgreSQL, no persistent worker. The demo-only request handler completes bounded deliveries against an internal synthetic sink. Production retains separate frontend/API/PostgreSQL/outbox/worker and scheduler.

Same-origin hosting preserves existing Secure/HttpOnly/SameSite=Lax cookies and CSRF. An independent frontend on pages.dev or vercel.app would need a same-origin API proxy or an owned domain design; simply enabling cross-site cookies/CORS would weaken the current contract. Cloudflare is a good later frontend/proxy option, but is not necessary for this initial low-traffic demo. No paid domain is needed.

Do not carry historical free allowances (Render 100 GB, Neon 0.5 GB, Fly perpetual free VMs, Railway unlimited free hosting) into a new deployment.

## $0 feasibility

Feasible for a small invitation-only demo, not guaranteed availability. Keep Render Hobby + Free compute and Neon Free, no card, no paid domains, no scheduled keepalive, no external integrations. Confirm account dashboard allowances before publication. The local client build is about 5.23 MB uncompressed; 5 GB transfer provides roughly 950 complete uncached bundle downloads before API/DB/other traffic (rough sizing, not a visitor guarantee). Browser compression/caching can help. Bot traffic can exhaust this budget.

The demo's request budget caps accepted API work but cannot stop every hostile request from reaching the process/database limiter. Provider suspension rather than spending is the financial backstop. Continuous DB activity could exceed 100 CU-hours/month; keep liveness checks DB-free and avoid readiness polling/keepalive. Free plans have no production SLA. Cold start affects the landing as well as API because both share Render. A later Cloudflare frontend plus carefully tested same-origin proxy can keep the landing warm, but would require separate preparation/approval.
